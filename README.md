# Event API

REST API сервис для управления мероприятиями.
Проект реализован на ASP.NET Core Web API.
Данные хранятся в памяти приложения и удаляются после перезапуска.

## Запуск проекта

Для запуска требуется .NET 10 SDK или выше.

1. Клонируйте репозитории: 

```bash
git clone https://github.com/dpqb658/EventApi.git
```

2. Перейдите в директорию проекта:

```bash
cd EventApi
```

3. Восстановите зависимости:

```bash
dotnet restore
```

4. Соберите проект:

```bash
dotnet build
```

5. Запустите приложение:

```bash
dotnet run
```

После запуска Swagger доступен по адресу:

```text
http://localhost:5232/swagger
https://localhost:7128/swagger
```

## Запуск тестов

Для запуска требуется xUnit.

1. Запустите в директории проекта:

```bash
dotnet test
```

## API

### GET /events

Получить список мероприятий.

Query-параметры:

* Заголовок `Title` регистронезависимый, ищет по частичному совпадению;
* Дата начала `From` не раньше указанной даты;
* Дата окончания `To` не позже указанной даты;
* Номер страницы `Page`;
* Количество элементов на странице `PageSize`;

Все переданные фильтры применяются одновременно по логике И.

Примеры:

```text
GET /events
GET /events?title=Мероприятие
GET /events?from=2026-09-01
GET /events?to=2026-09-30
GET /events?title=Мероприятие&from=2026-09-01&to=2026-09-30
GET /events?page=2&pageSize=5
GET /events?title=Мероприятие&page=2&pageSize=5
```

Пример ответа:

```json
{
  "items": [
    {
        "id": "9eb37363-3a96-4a87-9388-d0c819c4b4af",
        "title": "Заголовок мероприятия",
        "description": "Описание мероприятия",
        "startAt": "2026-09-15T10:00:00",
        "endAt": "2026-09-15T12:00:00"
    }
  ],
  "page": 1,
  "pageSize": 10,
  "totalCount": 18,
  "totalPages": 2
}
```

### GET /events/{id}

Получить мероприятие по идентификатору.

Пример:

```text
GET /events/9eb37363-3a96-4a87-9388-d0c819c4b4af
```

Если мероприятие найдено:

```text
200 OK
```

Если мероприятие отсутствует:

```text
404 Not Found
```

### POST /events

Создаёт новое мероприятие.
ID мероприятия генерируется автоматически.

Пример запроса:

```json
{
    "title": "Заголовок мероприятия",
    "description": "Описание мероприятия",
    "startAt": "2026-09-15T10:00:00",
    "endAt": "2026-09-15T12:00:00"
}
```

При успешном создании:

```text
201 Created
```

### PUT /events/{id}

Полностью обновляет существующее мероприятие.

Пример:

```text
PUT /events/9eb37363-3a96-4a87-9388-d0c819c4b4af
```

Тело запроса:

```json
{
    "title": "Заголовок мероприятия",
    "description": "Описание мероприятия",
    "startAt": "2026-09-15T11:00:00",
    "endAt": "2026-09-15T13:00:00"
}
```

При успешном обновлении:

```text
200 OK
```

Если мероприятие отсутствует:

```text
404 Not Found
```

### DELETE /events/{id}

Удаляет мероприятие.

Пример:

```text
DELETE /events/9eb37363-3a96-4a87-9388-d0c819c4b4af
```

При успешном удалении:

```text
204 No Content
```

Если мероприятие отсутствует:

```text
404 Not Found
```

## Обработка ошибок

Все необработанные ошибки обрабатываются в `GlobalExceptionHandlingMiddleware`.

Ответ имеет единый JSON-формат:

```json
{
  "statusCode": 404,
  "errorType": "NotFoundException",
  "message": "Мероприятие с идентификатором «...» не найдено."
}
```

Используемые статусы:

* `400 Bad Request` - Ошибка валидации параметров;
* `404 Not Found` - Мероприятие не найдено;
* `500 Internal Server Error` - Непредвиденная ошибка.

## Валидация

Для создания и обновления мероприятия выполняются следующие проверки:

* Заголовок `Title` обязателен для заполнения и длина не должна превышать 250 символов;
* Описание `StartAt` обязателен для заполнения;
* Дата начала `EndAt` обязателен для заполнения;
* Дата завершения `EndAt` должна быть позднее `StartAt`;
* Номер страницы `Page`должен быть больше либо равен 1.
* Количество элементов на странице `PageSize`должен быть больше либо равен 1.

При некорректных данных API возвращает:

```text
400 Bad Request
```

## Хранение данных

В проекте используется хранение данных в памяти приложения.
Мероприятия хранятся в `List<Event>` внутри `EventService`.
После перезапуска приложения все ранее созданные мероприятия будут удалены.
