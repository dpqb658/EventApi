# Event API

REST API сервис для управления мероприятиями и бронированиями.
Проект реализован на ASP.NET Core Web API.
Данные хранятся в памяти приложения и удаляются после перезапуска.

## Запуск проекта

Для запуска требуется .NET 10 SDK или выше.

1. Клонируйте репозиторий:

```bash
git clone https://github.com/dpqb658/EventApi.git
```

2. Перейдите в директорию проекта:

```bash
cd EventApi
```

3. Восстановите зависимости:

```bash
dotnet restore
```

4. Соберите проект:

```bash
dotnet build
```

5. Запустите приложение:

```bash
dotnet run
```

После запуска Swagger доступен по адресу:

```text
http://localhost:5232/swagger
https://localhost:7128/swagger
```

## Запуск тестов

Для запуска требуется xUnit.

1. Запустите в директории проекта:

```bash
dotnet test
```

## API Мероприятия

### GET /events

Получить список мероприятий.

Query-параметры:

* Заголовок `Title` регистронезависимый, ищет по частичному совпадению;
* Дата начала `From` не раньше указанной даты;
* Дата окончания `To` не позже указанной даты;
* Номер страницы `Page` начинается с 1;
* Количество элементов на странице `PageSize`;

Все переданные фильтры применяются одновременно по логике И.

Примеры:

```text
GET /events
GET /events?title=Мероприятие
GET /events?from=2026-09-01
GET /events?to=2026-09-30
GET /events?title=Мероприятие&from=2026-09-01&to=2026-09-30
GET /events?page=2&pageSize=5
GET /events?title=Мероприятие&page=2&pageSize=5
```

Пример ответа:

```json
{
  "items": [
    {
        "id": "9eb37363-3a96-4a87-9388-d0c819c4b4af",
        "title": "Заголовок мероприятия",
        "description": "Описание мероприятия",
        "startAt": "2026-09-15T10:00:00",
        "endAt": "2026-09-15T12:00:00"
    }
  ],
  "page": 1,
  "pageSize": 10,
  "totalCount": 18,
  "totalPages": 2
}
```

### GET /events/{id}

Получить мероприятие по идентификатору.

Пример:

```text
GET /events/9eb37363-3a96-4a87-9388-d0c819c4b4af
```

Если мероприятие найдено:

```text
200 OK
```

Если мероприятие отсутствует:

```text
404 Not Found
```

### POST /events

Создаёт новое мероприятие.
Id мероприятия генерируется автоматически.

Пример:

```json
{
    "title": "Заголовок мероприятия",
    "description": "Описание мероприятия",
    "startAt": "2026-09-15T10:00:00",
    "endAt": "2026-09-15T12:00:00"
}
```

При успешном создании:

```text
201 Created
```

### PUT /events/{id}

Полностью обновляет существующее мероприятие.

Пример:

```text
PUT /events/9eb37363-3a96-4a87-9388-d0c819c4b4af
```

Тело запроса:

```json
{
    "title": "Заголовок мероприятия",
    "description": "Описание мероприятия",
    "startAt": "2026-09-15T11:00:00",
    "endAt": "2026-09-15T13:00:00"
}
```

При успешном обновлении:

```text
200 OK
```

Если мероприятие отсутствует:

```text
404 Not Found
```

### DELETE /events/{id}

Удаляет мероприятие.

Пример:

```text
DELETE /events/9eb37363-3a96-4a87-9388-d0c819c4b4af
```

При успешном удалении:

```text
204 No Content
```

Если мероприятие отсутствует:

```text
404 Not Found
```

## API Бронирования

### Модель Booking

Структура:

* Уникальный идентификатор `Id` генерируется автоматически;
* Идентификатор мероприятия `EventId` обязателен для заполнения;
* Текущий статус `Status` при создании `Pending`;
* Дата и время создания `CreatedAt` заполняется автоматически при создании;
* Дата и время обработки `ProcessedAt` заполняется при изменении статуса;

Статусы бронирования:

* `Pending` - бронь создана, ожидает обработки;
* `Confirmed` - бронь подтверждена;
* `Rejected` - бронь отклонена;

### POST /events/{id}/book

Создаёт создаёт бронь для мероприятия
Id брони генерируется автоматически.

Пример:

```text
POST /events/9eb37363-3a96-4a87-9388-d0c819c4b4af/book
```

При успешном создании:

```text
202 Accepted
```

Если мероприятие отсутствует:

```text
404 Not Found
```

### GET /bookings/{id}

Возвращает текущее состояние брони.

Пример:

```text
POST /bookings/cb1a45a0-d889-41cb-8115-8a98b74aec68
```

Если бронь найдена:

```text
200 OK
```

Если бронь отсутствует:

```text
404 Not Found
```

Пример ответа:

```json
{
  "id": "cb1a45a0-d889-41cb-8115-8a98b74aec68",
  "eventId": "9eb37363-3a96-4a87-9388-d0c819c4b4af",
  "status": 0,
  "createdAt": "2026-10-04T21:00:00Z",
  "processedAt": null
}
```

## Сервис для фоновой обработки бронирований

Для обработки используется сервис `BookingProcessingService`, унаследованный от `BackgroundService`.

Фоновый сервис периодически проверяет очередь на наличие бронирований со статусом `Pending`.
Каждая запись обрабатывается 2 секунды, после обработки бронь переводится в статус `Confirmed`, а `ProcessedAt` заполняется текущей датой временем.

## Сценарий использования

1. Создаём мероприятие через `POST /events`.
2. Создаём бронь этому мероприятию через `POST /events/{id}/book`.
3. Получаем ответ, что бронь добавлена в очередь обработки со статусом `Pending`.
4. Проверяем статус через пару секунд `GET /bookings/{bookingId}` статус уже будет `Confirmed`, а `ProcessedAt` заполнен.

## Обработка ошибок

Все необработанные ошибки обрабатываются в `GlobalExceptionHandlingMiddleware`.

Ответ имеет единый JSON-формат:

```json
{
  "status": 404,
  "detail": "Мероприятие с идентификатором «...» не найдено."
}
```

Используемые статусы:

* `400 Bad Request` - Ошибка валидации;
* `404 Not Found` - Мероприятие или бронь не найдена;
* `500 Internal Server Error` - Непредвиденная ошибка.

## Валидация

Для создания и обновления мероприятия выполняются следующие проверки:

* Заголовок `Title` обязателен для заполнения и длина не должна превышать 250 символов;
* Описание `StartAt` обязателен для заполнения;
* Дата начала `EndAt` обязателен для заполнения;
* Дата завершения `EndAt` должна быть позднее `StartAt`;

Для пагинации:

* Номер страницы `Page` должен быть больше или равен 1;
* Количество элементов на странице `PageSize` должен находиться в диапазоне от 1 до 100.

## Хранение данных

В проекте используется хранение данных в памяти приложения:

* Мероприятия хранятся в `List<Event>` внутри `EventService`.
* Бронирования хранятся в `List<Booking>` внутри `BookingService`.

После перезапуска приложения все ранее созданные мероприятия и брони будут удалены.
